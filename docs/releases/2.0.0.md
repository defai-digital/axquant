# AXQuant 2.0.0

2.0 opens the **experimental CUDA / NVIDIA NVFP4** track. Apple Silicon / MLX
(MLX-LM, MLX-VLM, MLX-Audio) stays the primary and only certified conversion
path, and the certified PyPI pin remains `axquant[mlx]==1.8.1`. 2.0 does not
replace 1.8 convert or any certificate.

The 2.0 CUDA work is a development backend. Every generated manifest records
`status=development`, `runtime_verified=false`, and `quality_certified=false`.
No CUDA pack is a quality or speed certification, and no CUDA inference engine
or Tensor Core kernel is added here. AX Engine remains the Apple Silicon
runtime; AX Serving owns CUDA fleet deployment. NVFP4 is not a renamed MLX
MXFP4 pack: the two use different scales and block sizes.

## Changed

- **Native CUDA NVFP4 conversion (new `plan-cuda` / `convert-cuda` /
  `quantize-cuda`).** AXQuant-owned round-to-nearest (RTN) NVFP4 weight
  quantization; no AWQ. The default is **NVFP4 W4A16** (E2M1 FP4 weights,
  FP16/BF16 activations, protected tensors kept at source precision), with an
  opt-in calibrated **W4A4** path. It is separate from the MLX path, requires
  `axquant[cuda]` plus a CUDA-enabled PyTorch build, and fails instead of
  falling back to CPU. Plans contain portable identity and relative filenames,
  not source host paths.
- **Runtime MTP namespace protection for CUDA exports.** The complete integrated
  `mtp.*` namespace, including the virtual fused-expert projections that
  consumers add, is preserved at source precision. An ignore pattern that
  overlaps a tensor selected for NVFP4 now aborts conversion (fail-closed)
  instead of writing an ambiguous ignore list.
- **MXFP6 reference export retired (AXQ-051); MLX MXFP8 repacking stands.** The
  `export-mxfp6` command, the `axquant[mxfp6]` extra, and the
  `axquant.mxfp6-pack.v1` envelope are gone. `convert --q-mode mxfp8` performs
  native MLX E4M3 physical repacking; AX Engine compatibility must still be
  checked independently.
- **Publication identity hardening.** `plan` writes a source-plan binding
  sidecar (`axquant.source-plan-binding.v1`, AXQ-048) that `convert` carries into
  the artifact tree, and durable archive URIs in the evidence archive index v2
  must be scheme-qualified and host-independent (AXQ-049). Candidates now bind
  by artifact manifest digest rather than a local path.
- **Certificate withdrawal.** All per-pack certificate records were withdrawn on
  2026-10-03 pending re-certification; catalog tests now use synthetic fixtures.
  The live catalog therefore has no certified pack revision until
  re-certification completes.
- **README delisting.** The README no longer mirrors the per-pack matrix; the
  live catalog is the AutomatosX Hub org page.

## Added

- `axquant[cuda]` extra and CUDA schemas: `cuda-plan.v1`, `cuda-pack.v1`,
  `cuda-w4a4-plan.v1`, `cuda-w4a4-pack.v1`, and `cuda-activation.v1`. Frozen
  `cuda-fp8-*` definitions remain only as historical metadata; the FP8 converter
  and its publication were withdrawn.
- CUDA embedding export with preserved pooling semantics, BF16 protection, and
  bounded vector-drift checks (`docs/guides/cuda-nvfp4-embeddings.md`).
- `unlimited-ocr-v1` convertible adapter; Nemotron3 MTP packs and a streaming
  MLX convert that packs the large Lightning/Super sizes on a 192 GB host;
  `nemotron-mtp.v1`.
- Published CUDA development checkpoints: calibrated W4A4 previews
  (Qwen3-VL-4B/8B-Instruct, DeepSeek-OCR-2, Unlimited-OCR) and Nemotron
  Lightning/Super NVFP4 MTP packs.
- Guides `cuda-nvfp4.md`, `cuda-nvfp4-embeddings.md`, `microscaling.md`, and
  `nemotron-mtp-packs.md`; migrations `source-plan-binding.md`,
  `archive-uri-contract.md`, and `schema-property-restoration.md`.
- Schemas `reproduction.v4`, `scoreboard.v2`, and `evidence-archive-index.v2`.

## Fixed

- CUDA NVFP4 exports reject a selected NVFP4 tensor that overlaps the protected
  runtime MTP namespace.
- The Nemotron CUDA MTP smoke bounds the KV cache, exposes async scheduling, and
  requires positive draft-token counters; a stalled worker no longer retains GPU
  memory indefinitely.
- The planner records multi-candidate requests; convert emits oMLX
  compatibility and runtime support files and publishes through durable
  staging; certified publish retries Hub calls and verifies the remote file
  set; the publication privacy scan runs on every track.
- Oracle conformance fixtures were made path-neutral so source identity binds to
  bytes and immutable revisions, not to a local filesystem path.

## Operator action

- Keep certified production converts on `axquant[mlx]==1.8.1` until you choose
  to promote the MLX line; 2.0 does not change that pin.
- CUDA conversion: `python -m pip install 'axquant[cuda]'`, then `plan-cuda`
  followed by `convert-cuda`. Both stages require `--allow-unmeasured` because
  RTN is not measured activation sensitivity. Supply an original, unquantized
  checkpoint; already-quantized AWQ, MLX, or NVFP4 weights are rejected.
- Do not cite a CUDA development pack as quality, speed, or long-context
  certification. A GPU that can do the conversion is not automatically a
  supported NVFP4 inference target.
- Run real-model CUDA conversion and runtime checks on an NVIDIA test host, not
  on the Apple Silicon factory.
- 1.9 `joint-interaction.json` output stays development evidence only; never
  cite it as a public quality or speed claim.
