# AXQuant 2.2.1

Qwen3.5 and Qwen3.8 GDN input projections now share the inverse global
NVFP4 scale expected by fused runtime layers. The exporter groups
`in_proj_qkv` with `in_proj_z`, and `in_proj_b` with `in_proj_a`, including
when their source weights live in different shards. This avoids runtime
rescaling caused by mismatched scales in those fused projections.

Protecting either member preserves its entire fused pair and adds the
fused runtime module to the quantization ignore list. Regression tests
verify the stored scale values across shards and atomic protection.

Affected CUDA checkpoints must be regenerated from the original source;
changing configuration metadata alone cannot repair already packed bytes.
Existing source bindings and explicit unmeasured opt-in remain enforced.

This is a software correction, not model quality, MTP, speed, or runtime
certification. CUDA packs remain development artifacts. AXQuant 2.2.0's
DocLayout storage workflow remains available.

Validation: complete local CI mirror, including non-MLX and MLX suites,
plus cross-shard GDN conversion regression tests. Release CI provides the
published revision's independent checks.
