# AXQuant 1.9.0

1.9 is a **precision-allocator** toolkit release on **Apple / MLX**. It does
not replace 1.8 convert, `optimize`, affine U32 packs, or certificates.
Certified production converts may stay on `axquant[mlx]==1.8.1`.

CUDA, NVFP4, and a portable OCP MX interchange are out of 1.9. They are a
2.x line. `--q-mode mxfp4` remains the MLX Apple packer.

## Changed

- **Product line (AXQ-047).** Release planning now produces **MXFP4 (4-bit)**
  and **6-bit** packs. Affine 4-bit is retired from release planning: a 4-bit
  storage rung yields MXFP4 candidates only, and affine / DWQ / AWQ / GPTQ
  candidates exist at 6 bits and up. `--target-bpw 4.8` therefore shifts from
  affine 4-bit mixes to MXFP4 mixes. 8-bit and BF16 remain protection floors
  and explicit opt-in rungs, not headline offerings.
- **MXFP4 is a measured planning method (AXQ-046).** MXFP4 is selected per
  tensor from measured sensitivity like any other method, and `--q-mode mxfp4`
  is now an allow rather than a remap. Artifact schemas whose planning method
  changed are chain-bumped (`plan.v2`, `probe-config.v2`, `sensitivity.v2`,
  `refinement.v3`, and their siblings); old versions still load.
- **`publish` and `release-audit` reject unbound artifacts (AXQ-045).** A
  candidate must carry `axquant_evidence_binding.json`
  (`axquant.artifact-evidence-binding.v1`) next to `axquant_manifest.json`,
  and that sidecar must bind at least one Tier 1 / Tier 2 certificate file.
  This is a new fail-closed gate on the release path; migration and the
  one-time backfill command are in
  [docs/migrations/mtp-evidence-hardening-1.9.md](../migrations/mtp-evidence-hardening-1.9.md).
- **MTP manifest fields require a bound Tier 2 certificate.**
  `publish-prepare` writes `mtp_acceptance_retention` and
  `mtp_measured_speedup` only when the sidecar carries a Tier 2 binding.
- **Measured plans fail closed on unmeasured MTP sensitivity.** `plan`, the
  measured manual / experimental-mix paths, and measured joint reuse now
  reject a sensitivity report whose MTP-scoped modules are entirely the
  probe's `0.0` marker while the active profile weights that metric. Pass
  `--allow-mtp-unmeasured` to accept it with a recorded warning.
  Architecture-prior plans and plans without MTP modules are unaffected.
- **MTP runtime identity.** Resident-loadable Qwen 3.5/3.6/3.8 MTP sidecars
  carry the canonical `qwen3-next-mtp` identity used by strict oMLX import and
  MTPLX discovery. Metadata-only; existing exactness evidence is preserved and
  the Super-class SSD-stream pack stays outside the resident runtime contract.
- **MTP speed floors are per architecture class** (dense / MoE) instead of one
  global table, and Tier 1-only validation skips rather than fails MTP speed
  checks.

## Added

- `axquant diagnose-joint` enumerates a small `(weight BPW × KV bits × context)`
  grid under one memory budget and optionally computes
  `I(W, KV) = dQ(W, KV) − dQ(W) − dQ(KV)` from a BF16 baseline plus three
  matched treatment quality evaluations. Winners require `--kv-analysis`.
  Target BPWs below the architecture policy minimum are skipped instead of
  aborting the whole grid.
- `axquant plan-joint` turns that grid into a convert-ready development
  plan. Small I keeps 1.8 independent `optimize`. Material I ranks feasible
  cells with `additive + I * u(W) * u(KV)` and writes `axquant_plan.json`.
  Same effective `(weight BPW, per-layer KV)` reuses the independent plan.
- `axquant bind-artifact-evidence` writes the release evidence-binding sidecar
  from the final artifact plus its Tier 1 / Tier 2 certificate files.
- Measured MTP acceptance sensitivity: the probe can run a teacher-forced MTP
  forward and record a strictly-positive `mtp_acceptance_loss` per candidate,
  including sidecar reconstruction for `qwen3_5` and `qwen3_5_moe`
  checkpoints that ship MTP blocks outside the trunk. Backends without MTP
  forward keep the `0.0` marker, which is what the planning gate above
  detects.
- Tier 2 recertification records (`axquant.public-tier2-recert.v1`) for
  re-measuring an already-published pack on a current host.
- Family and runtime support: Ornith 1.5 convert path (MXFP4 and 6-bit),
  including a streaming MLX convert that packs the 397B size on a 192 GB host;
  Qwen3.8-Flash-Next with mixed group-size PLE; Gemma unified MTP in oMLX;
  DeepSeek-V4 Flash-0731 recipes.
- `axquant relayout-ngram-table` (byte-preserving n-gram table relayout for
  MTPLX compatibility) and `axquant annotate-omlx-mtp` (oMLX MTP sidecar
  annotation without requantizing).
- Development schemas `axquant.joint-interaction.v1` and
  `axquant.joint-selection.v1` (`certification_eligible=false`).
- Operator notes:
  [docs/guides/experimental-joint-interaction.md](../guides/experimental-joint-interaction.md),
  [docs/guides/mtp-hub-models.md](../guides/mtp-hub-models.md),
  [docs/guides/expert-ssd-stream.md](../guides/expert-ssd-stream.md).

## Fixed

- Explicit `tie_word_embeddings` at the top level is no longer discarded when a
  nested `text_config` omits the key (the nested value still wins when present).
- macOS seatbelt sandbox profile: one `allow process-exec` rule per entrypoint
  literal. Multiple literals in one SBPL rule are ANDed, so the previous
  rendering could never match when the invocation path differed from its
  resolved target.
- Whitespace-only campaign role identities are rejected instead of satisfying
  the named-accountability requirement.
- MTP norm contracts are preserved during requantization, and MTP shard
  isolation is gated by layout instead of guessed.
- Qwen tokenizer assets survive conversion; GDN `A_log` / `dt_bias` are written
  during streaming convert; the deprecated `mx.metal.clear_cache` call is gone.

## Operator action

- Keep certified production converts on `axquant[mlx]==1.8.1` until you
  choose to promote 1.9.
- Bind a release candidate before publishing: run `publish-prepare` first, then
  `axquant bind-artifact-evidence`, then `publish`.
- Campaign scripts replaying pre-retirement plans that contain affine 4-bit
  allocations must pass `--allow-legacy-4bit`.
- Run inspect / convert / diagnose-joint / plan-joint for real models on
  `df-macstudio-m2` + Ext16TR0, not on a laptop.
- Try `axquant plan-joint --help`. Output cannot authorize a Hub pack or
  certificate.
- Do not cite `joint-interaction.json` as a public quality or speed claim.
- Do not treat a 1.9 MXFP4 pack as an OCP or NVIDIA checkpoint.
