# AXQuant 2.3.0

AXQuant 2.3.0 is an official toolkit release with simpler format selection,
portable CLI discovery and independent AXQ contributor guidance. The package
no longer carries the Alpha development-status classifier. Toolkit release
status is separate from generated-model evidence and runtime certification.

## Install and convert

```bash
python -m pip install --upgrade 'axquant[mlx]==2.3.0'
axquant --version
axquant formats
axquant quantize /path/to/model-bf16 --format mxfp4
```

Use a virtual environment and Apple Silicon for MLX execution. CUDA users
install `axquant[cuda]==2.3.0` with a compatible CUDA-enabled PyTorch build and
use `axquant quantize-cuda --help` for the NVFP4 workflow targeting vLLM.

## Added and changed

- `quantize --format` selects `2bit`, `3bit`, `6bit`, `mxfp4` or `mxfp8`.
  Presets use group32 and keep higher protection floors. Defaults target base
  bits plus 0.8 BPW, subject to the existing policy-minimum adjustment. Without
  the option, the existing mixed prior planner still targets 4.8 BPW.
- `axquant formats --backend mlx|cuda` shows conversion choices and limitations
  without importing a runtime. `axquant --version` identifies the toolkit.
- Invalid ladder, budget, recipe and KV combinations fail before source
  resolution. Simple conversion rejects existing output paths before downloads.
- CI now builds and installs a wheel outside the checkout, checking base-only
  dependencies, package resources and installed console entry points.
- Documentation positions AXQuant as an independent MIT-licensed product and
  welcomes forks, independent AXQ integrations and first-time contributors.

## Compatibility and evidence

No artifact schema or certificate format changes. Existing protection floors,
source binding, atomic conversion and evidence gates remain enforced. Explicit
presets reject recipes, measured ladders, legacy affine4 and plans containing
no requested base-bit allocation. Output directory names identify the preset.

2/3-bit allocation is restricted to eligible MLP/expert tensors; runtime
experimental admission gates remain. MXFP8 uses unmeasured physical repacking
of unrefined affine8/group32 priors. CUDA NVFP4 remains a development export.

MLX-LM, MTPLX, oMLX and AX Engine are compatibility targets conditional on exact
model, format and requested features. This release does not establish universal
load/generation, MTP, quality or speed support, and does not certify a model.
Existing runtime/export restrictions and certificate scopes remain unchanged.

## Validation

Full local CI passed on the non-MLX and host MLX installation surfaces, including
lint, types, frozen schemas and certification-document checks. Format tests use
synthetic weights; native small-tensor packing checks cover all five MLX modes.
An isolated pip wheel-install smoke also passed. Integration-marked model/GPU
tests and a new complete cross-runtime model qualification campaign were not run
for this release. GitHub CI separately validates the release commit before tagging.
