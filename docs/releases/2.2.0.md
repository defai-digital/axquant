# AXQuant 2.2.0

2.2 adds source-bound AXDocLayout RT-DETRv2 development storage exports in
NVFP4, MXFP4 and MXFP8. The bundled reference loader reconstructs FP32
weights and runs PyTorch on CPU. This release does not add native low-precision
detector execution or grant quality, speed, or runtime-memory certification.
The package remains Alpha; the historical certified production pin stays 1.8.1.

## Added

- `quantize-doclayout --model PATH --revision SHA --q-mode nvfp4|mxfp4|mxfp8
  --allow-unmeasured --output PATH` supports the exact published
  `AutomatosX/AXDocLayout-M-v1.0` source revision. Source weight, metadata and
  inference-code digests bind conversion; existing destinations are protected.
- A `doclayout` installation extra supplies NumPy, PyTorch and Pillow. MX
  packing and decoding additionally require Apple Silicon MLX. NVFP4 reference
  packing and decoding do not import MLX.
- Versioned storage and compatibility envelopes record physical tensor layouts,
  padding, preserved tensors, file hashes and explicitly unsupported native
  runtimes. Existing language-model schemas remain unchanged.
- The reference loader validates integrity, exact state keys and dtypes,
  tensor accounting and nonfinite values. It accepts canonical Hugging Face
  cache blob links while rejecting arbitrary external symlinks. The pinned
  source's intentional positive-infinity proposal anchors remain preserved.
- Reproducible factory conversion, synthetic baseline/candidate smoke and
  immutable publication verification helpers accompany the
  [AXDocLayout collection](https://huggingface.co/collections/AutomatosX/axdoclayout-6acf4438c7708d288bf141d4).

## Validation and limitations

All three published packs pass strict full-weight loading, preserved-tensor
comparisons, finite-output checks on synthetic blank/text/table pages, complete
downloaded file-digest checks, and bundled-loader execution in isolated Python
processes. These are functional storage checks, not labeled quality evaluation.
Both 4-bit packs produce a blank-page false positive where FP32 returns none;
all formats change some synthetic-page detection counts. No FP32 accuracy
parity is claimed.

This release also resolves existing Ruff formatting and lint failures in the
conversion and collection helpers. Explicit `zip(strict=False)` declarations
preserve the previous truncation behavior; model-card text is unchanged.
Source archives now use an explicit input allowlist and exclude every local
`.venv*` directory, preventing alternate development environments from entering
the release bundle.

Install the detector development tools with:

```bash
python -m pip install 'axquant[doclayout]==2.2.0'
```

For the usual MLX toolkit, install `axquant[mlx]==2.2.0`.
See the [operator guide](../guides/doclayout.md) and
[schema migration](../migrations/doclayout-development-storage.md).
