# AXQuant 2.1.0

2.1 corrects peer-runtime export formats and binds compatibility checks to
new MLX conversion artifacts. It retains the Alpha packaging status and the
certified production pin `axquant[mlx]==1.8.1`. Runtime smoke and static checks
remain development evidence; they do not grant model quality or speed certificates.

## Added

- `check-runtime-compatibility` inspects current config, indexes, Safetensors
  headers, quantization modes, and MTP discovery separately for oMLX and MTPLX.
- `export-runtime --target omlx|mtplx` writes a distinct atomic variant with
  source bindings and its own file hashes. Unknown architecture profiles and
  unsupported formats fail closed. Exports do not silently requantize weights
  or reuse original certificates.
- Every new MLX convert/quantize output includes a manifest-bound
  `axquant_compatibility.json`. Publication and the Flash-Next factory driver
  recheck declared records and reject stale or unbound metadata.
- Frozen `axquant.runtime-compatibility.v1` and `axquant.runtime-export.v1`
  schemas, with launch environment, model settings, and modality restrictions.
- A bounded serial factory smoke runner for exact-model text/image generation
  with native MTP disabled and enabled; private command/state evidence remains
  separate from public artifact contracts.

## Fixed

- Flash-Next uses the native `qwen4-exp-mtp` identity rather than the dense
  Qwen3-Next sidecar importer. The oMLX export includes native MTP in its index.
- MTPLX n-gram exports concatenate rows in numeric shard order under canonical
  `ngram.weight/scales/biases`, preserving actual affine bits/group metadata.
  Table relocation alone no longer implies a complete runtime export.
- The Flash-Next MTPLX profile also rebases declared norm representation and
  splits/renames floating native MTP experts. Trunk precision is retained.
- Stock, streaming, and dequantizing MLX conversion paths forward `q_mode`,
  preventing MXFP8 weights from being advertised as affine. Compatible
  sidecar declarations are aligned with their actual files and formats.

## CUDA mixed six-bit development lane

- `--q-mode mix6` allocates native NVFP4 and FP8 E4M3 modules toward a
  language-trunk BPW budget (`--target-bpw`, default 6.0). This is a mixed
  4/8-bit storage class, not a native NVIDIA 6-bit datatype or MXFP6 revival.
- CUDA packs use format-qualified names such as `NVFP4-FP8-6bit`. The FP8
  encoder stays internal to this mixed lane; standalone CUDA FP8 checkpoints
  remain withdrawn. CUDA outputs remain development artifacts.

## Verified scope and operator action

The exact Flash-Next MXFP4 variants passed factory text generation with MTP
off/on and image generation in supported modes on 2026-10-06 using MTPLX
2.11.3 and oMLX 0.7.0.dev4. This is not a promise for all models or runtime
versions. MTPLX images require MTP mode; the measured oMLX setup requires
per-model `qwen4_ple_ssd_offload=true`. Honor the bound launch settings.
MTPLX MXFP8 exports remain blocked; do not relabel MXFP8 n-gram scales as
affine or synthesize biases.

Upgrade the development toolkit with:

```bash
python -m pip install --upgrade 'axquant[mlx]==2.1.0'
```

Existing weights generally need a runtime export rather than a full new
quantization. Keep original packs and use fresh directories for variants.
Historical reports remain versioned evidence. Regenerate missing compatibility
records through the supported conversion/export workflow; copying a report
from a different artifact cannot establish compatibility.
