# AXQuant 1.9.0b1

Superseded by [1.9.0](1.9.0.md). This file is the beta note.

This was an **experimental toolkit beta** for **Apple / MLX** smarter
allocation. It is not a certification release and does not change any
public pack, certificate, or 1.8.1 install pin. CUDA, NVFP4, and a
portable MXFP4 interchange are out of 1.9; they are a 2.x line.

## Added

- `axquant diagnose-joint` enumerates a small `(weight BPW x KV bits x context)`
  grid under one memory budget and optionally computes
  `I(W, KV) = dQ(W, KV) - dQ(W) - dQ(KV)` from a BF16 baseline plus three
  matched treatment quality evaluations. Winners require `--kv-analysis`.
- `axquant plan-joint` turns that grid into a convert-ready development
  plan. Small I keeps 1.8 independent optimize. Material I ranks feasible
  cells with a coupled proxy (`additive + I * u(W) * u(KV)`) and writes
  `axquant_plan.json`.
  The reports are development evidence only
  (`axquant.joint-interaction.v1`, `axquant.joint-selection.v1`,
  `certification_eligible=false`).
- Operator notes: [docs/experimental-joint-interaction.md](../experimental-joint-interaction.md).

## Changed

- Package version is `1.9.0b1`. Planning, convert, validate, and
  `verify-cert` paths are unchanged.

## Operator action

- Keep production converts on `axquant[mlx]==1.8.1`.
- Run inspect / convert / diagnose-joint / plan-joint for real models on
  `df-macstudio-m2`, not on a laptop.
- Try the I-gated search from a venv that has this branch installed:
  `axquant plan-joint --help`.
- Do not cite `joint-interaction.json` as a public quality or speed claim.
  A material `I(W, KV)` lets `plan-joint` pick a different feasible cell;
  it is not a certificate and not a task-score ranking.
- `--q-mode mxfp4` remains the MLX Apple packer. Do not treat a 1.9 MXFP4
  pack as an OCP or NVIDIA checkpoint.
