# AXQuant 3.0.0

AXQuant 3.0.0 makes AXQuant the MXFP / NVFP toolkit. It writes exactly five
storage formats: **MLX MXFP4, MXFP8 and BF16**, and **CUDA NVFP4 and BF16**.
This is a breaking release: affine integer storage, refined affine packing and
FP8 lanes are no longer produced. The release also carries the unreleased 2.3.0
work (official toolkit status, `axquant formats`, `axquant --version`).
Read the [3.0 migration note](../migrations/migration-v3.0.md) before upgrading.

## Install and convert

```bash
python -m pip install --upgrade 'axquant[mlx]==3.0.0'
axquant --version
axquant formats
axquant quantize /path/to/model-bf16 --format mxfp4
```

CUDA users install `axquant[cuda]==3.0.0` with a compatible CUDA-enabled
PyTorch build and use `axquant quantize-cuda --help` for NVFP4 targeting vLLM.

## Changed (breaking)

- MLX storage follows allocation bits: 4-bit is MXFP4, 8-bit is MXFP8 (both
  group 32), 16-bit is BF16. `convert` and `quantize` refuse any plan with
  2-, 3- or 6-bit allocations, 8-bit allocations at group 64 or 128, or AWQ,
  GPTQ, GPTQ-act or DWQ methods, before resolving the source.
- Protection floors that were affine 8-bit (token embedding, governed LM head,
  routers when quantized) are MXFP8. MXFP8 no longer requires
  `--allow-unmeasured`.
- `quantize --format` accepts `mxfp4` and `mxfp8` only. The default prior
  planner (no `--format`, 4.8 BPW) and the `prior`, `measured-lite` and
  `measured-full` ladders plan over MXFP4, MXFP8 and BF16 at group 32.
- Default output and `axquant name` names use the format:
  `AX-<model>-MLX-AXQ-MXFP4`, `-MXFP4-attn8` or `-MXFP8`.
- `convert --q-mode` accepts `mxfp4` or `mxfp8` and is ignored; `affine` is
  rejected. The top-level `config.json` quantization default is now the
  dominant quantized lane, so its bits always match its mode (2.x wrote
  `bits: 4, mode: mxfp8` under `--q-mode mxfp8`).
- `quantize-cuda` / `plan-cuda` / `convert-cuda` offer NVFP4 only
  (`--q-mode nvfp4`, W4A16 or calibrated W4A4).

## Removed

- `--allow-legacy-4bit` (analyze, plan, convert, quantize).
- `quantize --format 2bit|3bit|6bit`, the `refine-awq-dwq` ladder,
  `plan-experimental-mix` and `convert --calibration-activations`.
- `quantize-mtp-sidecar` (it wrote affine MTP sidecars).
- The CUDA mixed `NVFP4-FP8-6bit` lane (`--q-mode mix6`) and the FP8 encoder.
  Its plan and pack schemas stay readable for historical manifests.
- 38 affine example recipes. The 31 `*-axq-mxfp4-*` recipes now use
  `method: mxfp4` and group-32 MXFP8 floors.

## Added

- DFlash2 target identity: converting a checkpoint whose signature AX Engine
  admits as a DFlash2 target writes `axquant_dflash2_target.json`
  (`axquant.dflash2_target.v1`, admitted-signature table
  `axquant.dflash2_admitted_targets.v1`). Such conversions need a Hub source
  identity or an explicit `--not-dflash2-target REASON`. Publication checks the
  declaration. See [DFlash2 targets](../guides/dflash2-targets.md).
- Publication smoke: AX Engine's regenerated `model-manifest.json` and local
  `.cache/` upload state are not bound files; packs with an oMLX decision-head
  pair are smoke-tested on a chat-backbone copy and the receipt must say so.
- `axquant formats` and `axquant --version` (from the unreleased 2.3.0); the
  package no longer carries the Alpha classifier.

## Unchanged

- Inspection, analysis probes, validation, release audit and certificate
  verification still read existing affine packs, so published artifacts and
  certificates stay auditable. No artifact schema version changed.
- Protection policy, source binding, atomic conversion, `PlanPredicate`
  coverage and evidence gates are unchanged. Architecture-prior output remains
  development evidence.
- AX Engine, MLX-LM, MTPLX and oMLX remain compatibility targets conditional on
  exact model, format and features; this release certifies no model.

## Evidence for the MXFP8 floor

Before removing affine 8-bit floors, the same MXFP4 recipe was converted with
affine-8 and with MXFP8 floors on Qwen3.8-27B (dense; embedding and LM head)
and Qwen3.6-35B-A3B (MoE; embedding). On 64 WikiText-2 windows of 512 tokens,
MXFP8 changed perplexity by +0.09% and -0.09% respectively, with equal greedy
agreement against BF16 and slightly smaller packs. This is development
evidence, not a quality certificate.

## Validation

See the release commit's CI. Format behavior is covered by synthetic-weight
tests; integration-marked model and GPU tests were not part of this release.
