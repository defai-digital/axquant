# AXQuant 3.0.1

AXQuant 3.0.1 is a fix release for 3.0.0. Plans now budget MXFP4 and MXFP8 at
the storage they actually use.

## Install

```bash
python -m pip install --upgrade 'axquant[mlx]==3.0.1'
axquant --version
```

## Fixed

- Planning budgets count MX block scales. MXFP4 costs 4.25 BPW and MXFP8
  8.25 BPW (one E8M0 scale per 32 weights). 3.0.0 charged the retired affine
  overhead (5.0 and 9.0 BPW), so target BPW values read high against the bytes
  written and the default 4.8 BPW `quantize` target often started below the
  protection-floor minimum and was raised automatically. A plan's
  `effective_bpw` now matches the MX storage it describes.
- `plan-replay` accepts a source plan whose recorded `effective_bpw` matches
  either the 3.0.0 accounting or the new one, so existing plans still replay.
  The replayed plan reports the new accounting.
- The coding-suite sandbox no longer fails when macOS answers `EPERM` while
  killing a scorer process group whose members already exited.

## Changed

- The README links the AX Engine runtimes: [AX Engine](https://github.com/defai-digital/ax-engine)
  for MLX and [AX Engine for SGLang](https://github.com/defai-digital/ax-engine-sglang)
  for CUDA.

## Upgrade notes

- Re-planning the same model at the same target BPW can now choose more
  MXFP8 or BF16 tensors than 3.0.0 did, because the budget is no longer
  overstated. Keep an existing plan file to reproduce an earlier pack exactly.
- No artifact schema changed. Packs, plans and certificates written by 3.0.0
  stay valid.
